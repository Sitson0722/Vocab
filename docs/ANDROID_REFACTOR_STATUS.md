# Android 0.8 重构交付说明

本轮将 [统一设计](LEARNING_REDESIGN.md) 的核心学习闭环落实到 Android 源码。
构建、lint、单元与数据库测试仅通过现有 GitHub Actions 工作流执行。草稿 PR #1 的首轮 Actions 已通过：`lint`、`testDebugUnitTest` 和 `assembleDebug` 全部成功，用时 3 分 53 秒。APK 已由该工作流生成；尚未进行实体设备体验验证，也未发布版本。

## 已落入源码

- 首页只有一个开始入口；今天、词库、我的三个导航。默认每天 10 分钟，可选 5/15 分钟。
- 两条活跃能力：语境理解与产出；固定版本 FSRS-6 长期间隔，清除 UI 中的 L0–L5、三维总分和满 90 天毕业判断。
- 一轮最多五步，优先到期，按剩余时间限制新义项；按词形避让、受限错题回访、显式自愿加时。
- 首次教学、翻卡自评、短输入和审核示例的理解选择共用一条学习流。提示、答案暴露、不确定、评分来源、证据范围分别保存。
- 未能可靠判定的自由输入先核对再自评；不会仅因字符串不同自动判错。
- 房间数据库版本 4→5，保留旧历史与第三维；新增 Exposure 与 Runtime，以及可追溯的 Attempt。记录、调度、会话推进在同一事务内，作答键保证幂等。
- 当前题面、翻面、提示、输入草稿、反馈、每日预算、修复安排持久化；屏幕旋转/重建从相同状态继续。前台单调时钟计时，后台时间不加到学习用时。
- 撤销最近一次评分；撤销不能让已经看到的答案变成未暴露。报告材料会隔离材料、失效其可追溯尝试并重放对应维度进度。
- 义项状态从有效的延迟、客观、无提示、跨语境证据推导；到期或后续失败会重新显示待巩固。
- 六个离线示例义项、十二个审核语境。单词与义项聚合浏览；纯词汇先进入待补充，兼容旧五列格式与离线 JSON 词包。
- AI 后台补充按义项 ID 严格匹配，每批至多五个义项，输出 token 上限 2500，每天按用户设置至多 0/1/3 次。失败不退款、不循环重试，不影响本地学习。主动发起的 AI 释义提取单独说明。
- 备份格式 v2 包含新会话和证据；继续读取 v1，旧记录缺失的信息标未知。保留现有“完整备份包含密钥”的行为。

## 明确的实现取舍

1. 新义项教学后允许一次立即的引导回忆。这是冷启动例外，不更新长期间隔、不算独立证据；否则只有少量新词时，严格“先隔三个其他词”会让首次体验无法继续。
2. 普通选择/短输入优先补足客观作答，具备稳定样例后回到较轻的自评；没有合格理解选择材料时继续自评，保留待验证。
3. 新生成或旧导入的语境族默认未知。AI 自报场景标签与字面去重不能证明语义多样性，因此它们支持练习、但不冒充已审核的跨语境掌握证据。当前“较稳”的完整自动证据主要来自审核示例。更大规模的审核词包、语义校验与问题复核界面仍需后续内容能力。
4. 用时估计目前采用按题型的保守默认值；已有前台活跃用时日志。根据用户近期中位数估时和精细的三级负担恢复属于后续优化，不宣称已实现。
5. 自由造句、发音/听力评价、可靠的同义词自动诊断、完整义项目录与语义去重没有在本轮冒充完成。

## 验证入口

现有 Actions 原样执行：`./gradlew lint testDebugUnitTest assembleDebug --stacktrace`。

新增/更新的测试覆盖：

- FSRS 官方固定版本的 17 组数值对照，两维一致规则、提示映射与非法输入。
- 延迟/跨日/跨语境门槛、提示与自评排除、后续遗忘与裸搭配证据限制。
- 时间预算、逾期优先级与同词冷却。
- Room 实际 v4→v5 迁移校验；旧记录和归属保持。
- 离线教学闭环、独立更新、幂等提交、持久化反馈、提示、无法判分、跳过、报告重放、撤销、旧引擎切换、预算与补充额度。
- 新旧备份兼容、错误引用拒绝、生产题正面不泄露目标词。

GitHub Actions 已给出成功的编译、lint、测试和 Debug APK 构建结果。APK 实机上的软键盘、TalkBack、大字号与恢复体验还需要安装包验证。

签名发布工作流位于 `.github/workflows/release.yml`。它只从 GitHub Secrets 还原长期签名密钥，执行检查、测试与 Release APK 构建，使用 `apksigner` 验证签名，输出 SHA-256，并在 `v*` 标签下发布 Release。缺少任何签名 Secret 时会明确失败，不生成一次性密钥或伪装成正式包。
